# τ-Voice Benchmark Context & Evaluation Methodology

## 1. Benchmark Specification

* **Benchmark Name**: **τ-Voice** (built upon Sierra Research's `tau2-bench`).
* **Source Repository**: `vendor/tau2-bench/` in this repository.
* **Evaluation Scope**: 278 enterprise service tasks across 3 domains:
  * **Airline**: 50 tasks (flight booking, cancellations, seat changes, baggage, compensation).
  * **Retail**: 114 tasks (order tracking, returns, exchanges, address updates, cancellations).
  * **Telecom**: 114 tasks (network troubleshooting, APN reset, SIM lock, line suspensions, data refuels).
* **Communication Mode**: Full-duplex voice (`CommunicationMode.FULL_DUPLEX`), simulating simultaneous bidirectional speech with interruptions and backchanneling.

---

## 2. Pass@1 Definition & Evaluation Metrics

In τ-Voice, a task is scored as **Pass@1** if and only if the final evaluation reward equals `1.0`:
$$\text{Pass@1} = \mathbb{I}(\text{reward} = 1.0)$$

The reward is computed by the official evaluator (`vendor/tau2-bench/src/tau2/evaluator/evaluator.py`). Depending on the evaluation configuration, the evaluator checks:
1. **Database / Environment State (`EvaluationType.ENV`)**: Compares the simulated database state (e.g., ticket cancellation status, order records, SIM status) against deterministic gold assertions.
2. **Action Trajectory (`EvaluationType.ACTION`)**: Verifies that required gold tool calls were dispatched and forbidden actions were avoided.
3. **Natural Language Assertions (`EvaluationType.NL_ASSERTIONS`)**: Prompts an external LLM (e.g. OpenAI GPT-4o-mini via LiteLLM) to evaluate whether agent conversational utterances satisfied explicit user requirements.
4. **All Criteria Combined (`EvaluationType.ALL`)**: The task passes if and only if **all** active sub-evaluators score 1.0.

## 3. Offline Frozen Replay Methodology

The evaluation conducted in this repository operates on **recorded benchmark trajectories**:
* **Source Trajectories**: 281 trajectory JSON files stored in `artifacts/tau_voice/official_trajectories/` (278 unique task IDs).
* **Trajectory Structure**: Each trajectory consists of sequential discrete time slices (`ticks`), containing:
  * `user_chunk`: Synthesized user speech chunks and gold transcripts.
  * `agent_tool_calls`: Tool calls dispatched by Gemini 2.0 Flash during the recorded live session.
  * `agent_tool_results`: Responses returned by the environment simulator to the agent.
  * `agent_speech`: Audio packets generated by Gemini.

### Fundamental Constraints of Frozen Replay:
1. **Fixed Conversation Future**: Because trajectories are recorded, **model actions cannot alter future user behavior**. If an agent guardrail suppresses an action or normalizes an argument, the recorded user will not dynamically reply with clarification turns.
2. **No Interactive Clarification Loops**: When the Entity Resolver detects an ambiguous customer identity or the Policy Engine flags missing information, a production voice agent would verbally ask the customer for clarification. In frozen replay, such conversational repair is unobservable; the trajectory simply proceeds along its pre-recorded script.
3. **Dual-Control Execution**: In the Telecom domain, the benchmark simulates user-side device operations (`toggle_airplane_mode`, `reset_apn_settings`, `reseat_sim_card`). In live generation, Gemini directly invoked these tools. Under strict production role gating (`ActorBoundaryGate`), the agent is forbidden from executing user-side tools, requiring the user to execute them. In frozen replay, the offline simulated user cannot take over execution, creating an artificial task failure.

## 4. Agent Visibility & Information Access

* **Permitted Information**:
  * User audio and transcripts delivered in the current or prior turns.
  * Schema definitions for tools registered to the agent's domain.
  * Return values from read-only tools dispatched during the session (e.g., `get_reservation_details`, `get_order_details`, `get_customer_by_phone`).
* **Forbidden Information (Oracle Information)**:
  * Target gold action sequences (`task.evaluation_spec`).
  * Target database end-states.
  * True user intent annotations not uttered in conversational speech.
  * Hidden database entries not queried via official domain tools.
